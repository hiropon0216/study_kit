# フェーズ0：ヒアリング

ヒアリングの目的は、章立ての前に「この学習者のための教材」に必要なことをそろえること。

## 原則

1. **聞くのは、答えによって教材の中身が変わることだけ。** 下の「聞くことと、教材のどこが変わるか」の表にない質問はしない
2. **調べれば分かることは聞かない。** 試験の形式（問題数・制限時間・合格ライン）、出題範囲、最新の版や改正は、こちらで調べて要約の中で「こう調べました」と確かめる。学習者に調べさせない
3. **起動のときの依頼文から読み取れることは聞き直さない。** 読み取ったことは、最初のメッセージで「こう受け取りました」と一行で示す
4. **往復は2回を目安にする。** 1往復目で、目的に合わせた質問を2〜4個まとめて聞く。2往復目でゴールの要約を出して確かめる。答えから新しく決めなければならないことが出たときだけ、1往復足す
5. **答えにくい質問には答えの例を添える。** ただし例は目的に合わせて具体的に書く。選択肢を並べると答えが選択肢に引っぱられるので、自由に書いてもらう形にする

なぜこうするか：以前は3点（トピック・目的・知識レベル）と、ゴールを具体にする4観点（使う場面・外れの例・試したこと・優先度）を1つずつ聞いていた。資格試験の学習者に「使う場面」と「優先度」を聞いたところ、「合格できること」と同じ答えが返り、往復だけが増えた。資格試験のゴールは最初から「合格」に決まっている。一方で、教材を大きく変える「手元の教本の目次」は聞いていなかった。

## 聞くことと、教材のどこが変わるか

| 聞くこと | 教材のどこが変わるか | 資格 | 実務 | 教養 |
|---|---|---|---|---|
| 手元の教材・資料（教本・問題集・シラバス・社内の手順書）と、その目次 | 章の順番と範囲を手元の教材に合わせる。用語の表記を合わせる。リサーチの出発点（信頼度 S の資料なら最優先で使う） | ◎ | ○ | ― |
| いまの状況（どこまで進んだか・模試や過去問の手ごたえ） | 章立ての出発点。重要度 A の節 | ◎ | ― | ― |
| いまできること（「〜ができる」の形で） | 前提にしてよい知識。固有名詞の説明の厚さ | ○ | ◎ | ○ |
| 不安なところ・つまずいたところ | 重要度 A の節。まぎらわしい項目の組（`confusables`）。予告問題の誤りの選択肢 | ◎ | ○ | ― |
| 使う場面（教材を終えたあと、どんな場面で何をしていたいか。直近で困った場面） | ゴール（「〜できる」）。総合演習の場面 | ― | ◎ | ○ |
| 環境（バージョン・OS・クラウド・使っているツール） | 対象バージョン。例に出すコマンドや画面 | ― | ◎ | ― |
| よく知っている分野（仕事・趣味・ほかに学んだこと） | 本文のたとえと具体例をその分野から取る（すでに知っていることと結びつけると、新しい知識が残りやすい） | ○ | ○ | ◎ |
| きっかけ（何を知りたくなったか）とどこまで知りたいか | ゴール。扱う深さと「扱わないもの」 | ― | ― | ◎ |
| これだと外れ（教材がどうなっていたら「欲しかったのはこれじゃない」か） | 「扱わないもの」。レビューで論点のズレを判定する基準 | ○ | ◎ | ○ |

◎ は1往復目に必ず聞く。○ は依頼文から読み取れなければ聞く。― は聞かない。

- 目的は `meta.purpose` の「資格」「実務」「教養」のどれかに対応させる。依頼文から決まらないときだけ、1往復目に目的も聞く
- 資格のゴールは「合格」に決まっているので、使う場面と優先度は聞かない。重要度 A の節は、出題の多い分野（シラバスの配点・出題数の調べ）と学習者の不安なところから決める
- 手元の教材の本文は書き写さない。目次（章や項目の名前）と範囲だけを使い、本文と問題は信頼度 S・A の出典から新しく作る。手元の教材があるときは、目次を貼ってもらえるよう頼む（写真でもよい）
- 「おまかせ」と言われた項目は、こちらで決めた内容を要約の「こちらで決めたこと」に書く。伝えずに決めない

## 聞かないこと

- 期限・1日の学習時間（学習エンジンの設計に使わないため）
- 自信の度合い（自己申告はさせない方針のため）
- 説明の厚さの好み（説明は丁寧に、図を多く、が全教材の方針のため）
- 調べれば分かること（試験の形式・出題範囲・最新の版）

## 1往復目のメッセージ

依頼文から読み取ったことと、調べて分かったことを先に書き、そのあとに質問をまとめる。調べるのは、試験の形式のように数回の検索で確かめられることだけにする（本格的なリサーチはフェーズ2）。

資格の例：

```
仮免許の学科試験の教材として進めます。依頼文からこう受け取りました。
- 目的：合格（「間違いなく合格できる」水準）
- 試験の形式（調べました）：○×式 50問・30分・45問以上の正解で合格
- 手元の教材：『〇〇』（教本）と『△△』（問題集）

教材の中身を決めるために、3つ教えてください。
1. 手元の教本の目次（章や項目の名前だけで十分です。写真でもかまいません）
   → 章の順番と範囲を教本に合わせます
2. いまの状況（教習所の学科を何時限まで受けたか、問題集を解いたことがあるか）
   → どこから説明を始めるかを決めます
3. 不安なところや、覚えにくいと感じるところ（なければ「なし」で大丈夫です）
   → その分野の問題を多くします
```

実務の例：

```
Kubernetes を実務で使えるようになるための教材として進めます。

教材の中身を決めるために、3つ教えてください。
1. 教材を終えたあと、どんな場面で何をしていたいですか。直近で困った場面があれば、それも教えてください
   （例：社内の検証クラスタで Pod が起動しないとき、自分で原因を調べたい）
2. いまできることと、使っている環境（例：Docker は毎日使う。Kubernetes は触ったことがない。社内は EKS の 1.33）
3. 教材がどうなっていたら「欲しかったのはこれじゃない」と感じますか（例：概念の説明ばかりでコマンドを打つ場面がない）
```

教養の例：

```
宇宙論を教養として学ぶ教材として進めます。

1. 何がきっかけで知りたくなりましたか。どこまで分かるようになりたいですか（例：ニュースの「宇宙の加速膨張」を人に説明できるくらい）
2. よく知っている分野や、仕事・趣味を教えてください → たとえ話をその分野から取ります
3. 理科や数学について、いまどのくらいなら読めますか（例：高校の物理はほぼ忘れた。数式は少しならよい）
```

## ゴールの要約と確認（2往復目）

聞き取りが済んだら、次の形で要約を返し、違っている点を直してもらう。学習者が言ったこと・調べたこと・こちらで決めたことを分けて書く。

```
## 学習のゴール（要約）
- トピック／目的：…
- いまできること・いまの状況：…（学習者の言葉）
- 教材を終えたあとの場面：…（学習者の言葉。資格なら「合格」）
- 不安なところ：…（学習者の言葉）
- これだと外れ：…（学習者の言葉）
- 手元の教材：…（目次をもらったか）
- 調べて確かめたこと：…（試験の形式・出題範囲・対象バージョンなど。出典つき）
- こちらで決めたこと（違っていたら直してください）：…（範囲・説明の始め方・重要度 A にする分野・たとえを取る分野・出力先）
```

- 学習者が「合っている」と言うまでフェーズ1に進まない
- 確定した要約を `<出力先>/work/goal-brief.md` に保存する。フェーズ1以降のレビュー担当（サブエージェント）は、この文書をゴールの基準として読む
- 手元の教材の目次をもらったら、`<出力先>/work/source-toc.md` に保存する。章立てとリサーチで使う
