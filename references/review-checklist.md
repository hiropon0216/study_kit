# フェーズ4：レビュー観点

順番は 事実チェック → 表現の改修 → 意味の差分チェック → リント → 整合性チェック。入れ替えない。

## 1. 事実チェック（生成担当とは別のエージェントが行う）

教科書の各文・各問題の正解・各解説について、次を確かめる。

- [ ] ファクトシートのどの事実が根拠か特定できる
- [ ] 根拠の事実と内容が食い違っていない（数値・条件・範囲・バージョン）
- [ ] 事実の強さが変わっていない（「〜の場合がある」を「〜する」と言い切っていない、その逆もない）
- [ ] 正解が1つに決まる。ほかの選択肢が条件次第で正解にならない
- [ ] 穴埋めの許容表記に漏れがない
- [ ] 並べ替えの正しい順が1通りに決まる
- [ ] 節の `sources` に、本文が使った事実がそろっている
- [ ] 固有名詞（`references/proper-nouns.md` の対象）がすべて、初出の節で `sk-premise` か本文によって前提から説明されている。4つの観点のうち「何か」と「この教材との関係」が欠けていない
- [ ] 問題文・選択肢・解説・コードに、前提を説明していない固有名詞が出ていない

説明のない固有名詞を見つけたら、`sk-premise` を初出の節に足す。必要な事実はファクトシートにない記述と同じ手順（下記）で集める。

ファクトシートにない記述が見つかったら、追加リサーチを1回行う。

- S か A の出典が見つかった → ファクトシートに事実を追加し、`sources` に加える
- 見つからない → 記述を削除する。問題なら差し替える
- どちらの場合も `factCheckLog` に記録する

報告の形式：

| 場所 | 記述 | 判定 | 根拠の事実ID／対応 |
|---|---|---|---|
| ch1-s2 本文3段落目 | 「〜」 | OK | F-005 |
| q-ch2-s1-03 解説 | 「〜」 | NG（ファクトシートにない） | 追加リサーチ → F-015 を追加 |

## 2. 表現の改修

- [ ] yomiyasu の SKILL.md を読み込み、ドメイン `tech` で適用した
- [ ] 対象は `extract_prose.py` が抜き出した地の文と解説文だけ
- [ ] `<!-- prose: ID -->` の目印を消していない・順番を変えていない
- [ ] `sk-premise` の段落を短くしすぎていない。冒頭の `**何か：**` などの見出しを消していない（前提の説明は情報密度より分かりやすさを優先する）
- [ ] `apply_prose.py` がエラーなしで書き戻せた

## 3. 意味の差分チェック

`yomiyasu_diff.py --stance=説明` の出力と、改修前後の文を見比べる。

- [ ] 「〜の場合がある」「〜ことが多い」が断定になっていない
- [ ] 条件（「〜のとき」「〜なら」）が落ちていない
- [ ] 数値・単位・バージョン・コマンド名・オプション名が変わっていない
- [ ] 主語や対象が入れ替わっていない（Deployment が作る／ReplicaSet が作る、など）
- [ ] 否定が肯定になっていない、その逆もない
- [ ] 固有名詞の前提の説明（何か／誰が作ったか／なぜ必要か／この教材との関係）が削られていない

意味が変わっていたら、改修前の意味に戻す。

- [ ] 残した警告は理由を記録した（段落をまたいだ文末の連続、専門用語の前後の空白など）

- [ ] `validate.py` のエラーが0件
