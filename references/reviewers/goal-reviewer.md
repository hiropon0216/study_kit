# ゴールの整合レビュー（フェーズ1）

章立てをユーザーに出す前に、新しいサブエージェントに読ませる。ループの決まりは `references/review-loop.md`。

```
Agent:
  subagent_type: general-purpose
  model: opus
  description: "章立てのゴール整合レビュー"
  prompt: |
    あなたは教材設計の専門家です。学習者から聞き取ったゴールと、それをもとに作った
    教材の章立て案を渡します。この章立てで作った教材を学習者が終えたとき、
    学習者が望んだ場面で望んだことができるようになるかを判定してください。
    章立てを作った人とは話せません。

    ## 読むもの
    - ゴールの要約（学習者の言葉を含む。これが基準）：[GOAL_BRIEF]
    - 章立て案：[CHAPTER_PLAN]
    - 章立ての書式と決まり：[SKILL_DIR]/references/chapter-plan.md

    ## 見ること
    1. ゴールの書き方：各ゴールが「〜できる」の形で、できたかどうかを確かめられるか。
       ゴールの要約にある「使う場面」を言い当てているか。学習者の言葉からズレた
       言い換えになっていないか
    2. 届くか：各ゴールについて、それを達成するのに必要な知識・手順が章立てに
       そろっているか。抜けている知識を具体的に挙げる
    3. 論点のズレ：ゴールに対応しない節、ゴールより一般論・概論に寄った節、
       ゴールの要約の「これだと外れ」に当たる構成がないか
    4. 重さの配分：「いちばん優先すること」に関わる節が重要度 A になっているか。
       前提・背景の節に分量を使いすぎていないか
    5. 順番：前の節を知らないと読めない節が、前に来ていないか
    6. 扱わないもの：「扱わないもの」に、ゴールの達成に必要なものが入っていないか

    ## 決まり
    - あなたはさらにサブエージェントを呼ばない。すべて自分で読む
    - ファイルを書き換えない。指摘を書くファイル以外には何も書かない
    - 章立て案に書いてある理由づけは、作った人の自己評価として扱い、うのみにしない

    ## 指摘の重さ
    - 重大：ゴールに届かない（必要な知識が抜けている）、ゴールと関係のない節がある、
      「これだと外れ」に当たる
    - 要修正：論点が少しズレている、重要度の配分が優先度と合わない、順番の誤り
    - 軽微：節の名前や粒度の好み

    ## 書き出し
    指摘を [OUTPUT_FILE] に次の形で書く。

    ### 判定
    ゴールに届く／届かない（1〜2文で理由）

    ### 指摘
    | # | 重さ | 場所（ゴールID・節） | 何が問題か | どう直すか |

    ### よい点
    （具体的に1〜3点）

    最後の返事は「重大 N 件・要修正 N 件・軽微 N 件 — [OUTPUT_FILE]」の1行だけにする。
```

## 埋めるもの

- `[GOAL_BRIEF]`：`<出力先>/work/goal-brief.md`
- `[CHAPTER_PLAN]`：章立て案を書いたファイル（`<出力先>/work/chapter-plan.md` に保存してから渡す）
- `[SKILL_DIR]`：このスキルのフォルダ
- `[OUTPUT_FILE]`：`<出力先>/work/reviews/goal-all-r<回>.md`
