# 再レビュー（各ループの r2 以降）

作成担当が指摘を直したあと、新しいサブエージェントに読ませる。見るのは「指摘が直ったか」と「直した箇所が新しく壊れていないか」だけ。直していない箇所を読み直して新しい指摘を探すことはしない（ループが終わらなくなるため）。ループの決まりは `references/review-loop.md`。

```
Agent:
  subagent_type: general-purpose
  model: sonnet
  description: "再レビュー [席] [範囲] r[回]"
  prompt: |
    あなたは教材の再レビュー担当です。前回のレビューで出た指摘と、作成担当が
    直した結果を渡します。指摘が1件ずつ直ったかを判定してください。

    ## 読むもの
    - 前回の指摘：[FINDINGS_FILE]（重大・要修正の行が対象。軽微は見ない）
    - 直す前の教材JSON：[BEFORE_JSON]
    - 直した後の教材JSON：[AFTER_JSON]
    - 作成担当の修正メモ（どの指摘をどう直したか）：[FIX_NOTE]
    - 事実の基準：[FACTSHEET]
    - ゴールの基準：[GOAL_BRIEF]

    ## 見ること
    1. 指摘ごとに、直した後の該当箇所を読み、「直った」「直っていない」を判定する。
       修正メモに「直した」とあっても、教材JSONで確かめる
    2. 直した箇所が新しく壊れていないか：事実の意味（条件・数値・強さ・主語）が
       変わっていないか、ファクトシートにない記述が増えていないか、
       同じ項目のすぐ確認の正解が本文と食い違っていないか
    3. 直した箇所の外で気づいたことは、ループに入れず「範囲外」として書くだけにする

    ## 決まり
    - あなたはさらにサブエージェントを呼ばない
    - ファイルを書き換えない。判定を書くファイル以外には何も書かない

    ## 書き出し
    [OUTPUT_FILE] に次の形で書く。

    ### 判定
    | 前回の # | 直った／直っていない | 根拠（直した後の記述の引用） |

    ### 直した箇所で新しく壊れたもの
    | # | 重さ（重大／要修正） | 場所 | 何が問題か | どう直すか |

    ### 範囲外（記録のみ）

    最後の返事は「直った N 件・直っていない N 件・新しく壊れた N 件 — [OUTPUT_FILE]」の1行だけにする。
```

## 埋めるもの

- `[席]`：`goal`・`validity`・`clarity`・`final`
- `[FINDINGS_FILE]`：前回の指摘のファイル（初回なら r1、以降は前回の再レビューの「直っていない」「新しく壊れたもの」）
- `[BEFORE_JSON]`：直す前に `<出力先>/work/content_before_<席>_r<回>.json` へコピーしておいたもの
- `[AFTER_JSON]`：`<出力先>/content.json`
- `[FIX_NOTE]`：`<出力先>/work/reviews/<席>-<範囲>-r<回>-fix.md`（作成担当が、指摘の # ごとにどう直したか、直さなかったならなぜかを書く）
- `[FACTSHEET]`・`[GOAL_BRIEF]`：妥当性レビューと同じ
- `[OUTPUT_FILE]`：`<出力先>/work/reviews/<席>-<範囲>-r<回>.md`

フェーズ1のゴール整合レビューでは、教材JSONの代わりに章立て案の直す前・直した後を渡す。
