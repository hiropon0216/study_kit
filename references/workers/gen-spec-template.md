# 生成の共通仕様（テンプレート）

フェーズ3で、章ごとに別のサブエージェントが教材を書く。全員が同じ決まりで書けるよう、作成担当は書き始める前にこのテンプレートを埋めて `<出力先>/work/gen-spec.md` に保存する。章を書くサブエージェントには、このファイルのパスを渡す（中身をプロンプトに貼らない）。

`[ ]` の部分を埋める。トピックに固有の注意は「事実の注意」と「固有名詞の割り当て」に書く。

````markdown
# 生成の共通仕様：[教材名]

この教材は study-kit スキル（`[SKILL_DIR]`）で作る。章ごとに別のエージェントが書き、最後に `scripts/assemble.py` で1つの `content.json` にまとめる。全員がこの仕様に従う。

## 必ず読むもの（書き始める前に）

1. `[SKILL_DIR]/references/content-schema.md`（JSON の構造。最重要）
2. `[SKILL_DIR]/references/textbook-components.md`（本文の部品。図は必須。「具体 → 抽象」）
3. `[SKILL_DIR]/references/question-guide.md`（問題の作り方）
4. `[SKILL_DIR]/references/proper-nouns.md`（固有名詞の前提の説明）
5. `[出力先]/factsheet.md`（事実はここに載っているものだけを使う。自分の章の節番号が「使用箇所」にある行を中心に読む）
6. お手本：`[SKILL_DIR]/examples/k8s-practical/content.json` の第1章（構造・部品・問題の書き方をそろえる。事実は流用しない）。Python で `json.load(open(..., encoding='utf-8'))` して読むと文字化けしない

## 学習者とゴール

- 学習者：[goal-brief.md の「いまできること」と「使う場面」を2〜3文で]
- 目的：[資格／実務／教養]。[学習者が欲しいもの・外れの例から、書き方の方針を1〜2文で]
- ゴール（`meta.goals`）
  - G1 [ ]
  - G2 [ ]
- 対象バージョン：[ ]

## 章立て（承認済み。変えない）

| 節ID | 節タイトル | 重要度 | 項目 | すぐ確認の最低数 |
|---|---|---|---|---|
| ch1-s1 | [ ] | [A/B/C] | ①[ ] ②[ ] | [ ] |

- 章タイトル：ch1「[ ]」、ch2「[ ]」…
- 各章の章末演習は **10〜12問**（`q-chN-ex-01` …）。各節から偏りなく、すぐ確認より一段深く（predict・場面への当てはめ・見分け）。`refs` は `chN-sM#iK` の形で項目まで指す
- 総合演習は別のエージェントが後で作る。章の担当は作らない

## 固有名詞の前提（sk-premise）の割り当て

章立ての「固有名詞の一覧」から作る。`data-term` はこの表記どおりに書き、本文でもこの表記で使う。見出しは本文より先に読まれるので、見出しに初出の語を入れない。

| data-term | 置く節 | 注意 |
|---|---|---|
| [ ] | [ ] | [ ] |

- 節の主題そのものの語は sk-premise を置かず、その節の最初の項目の冒頭で「何か」と「なぜ必要か」を書く。主題の節より前の章で、これらの語を出さない
- 上の表にない固有名詞は、できるだけ出さない。どうしても出すなら、その節に sk-premise を置き、報告に書く

## 書き方のルール（要約。詳細は references）

- 本文の地の文は属性なしの `<p>`。`<p>` の中のタグは `<code>` `<strong>` `<a>` だけ
- 説明の項目には図や表を必ず1つ以上。`sk-figure`（SVG）を各節に1つ以上は入れる。図の `figcaption` は「図 2-2-1　〜」（節番号-通し番号）
- SVG の marker の id は教材全体で重ならないよう `ah-c{章}s{節}-{名前}` にする。色はクラスで指定。`viewBox` 必須、`width`/`height` は書かない
- 原理を説明する項目は「具体的な場面2つ → 共通点 → 原理の名前」の順
- `<strong>` は伏せ字になる。覚えてほしい1語〜10字程度だけ
- 本文の `<pre><code>` 内の `<` `>` `&` はエスケープする。問題の `code` はプレーンテキスト
- 文体は「です・ます」。誰が何をするかが分かる文にする。避ける表現：無生物主語（「この設定が〜を可能にする」）、比喩的な動詞（「〜を支える」「〜を担う」）、「〜と言えるでしょう」「重要なのは〜」「まさに」、文末のコロン、絵文字、不要なカッコ書き、「〜ではなく〜だ」の多用
- まぎらわしい組は `confusables` に。組の項目には `sk-compare` を置く

## 問題のルール（要約）

- すぐ確認はその項目を読めば解ける問題。問題文だけで何を問うか分かる形（予告問題で先に見せる）
- 形式を偏らせない（choice／truefalse／fill／order／predict）。predict は `code` 必須。fill の answer には半角英数字の表記を必ず1つ
- choice には `optionNotes` を付ける
- 重要度 A の節のすぐ確認の半分以上と、章末演習の半分以上に `variants` を1個付ける。形式を変える。ID は元のIDに `-v1`
- 引っかけ・二重否定・「上のすべて」・「分からない」の選択肢は禁止

## 事実の注意

- 本文・問題・解説は factsheet.md の事実だけで書く。節の `sources` には実際に使った事実IDをすべて入れる
- [リサーチで分かった、取り違えやすい事実や断定してはいけない事実]
- どうしても必要な事実がファクトシートにないときは、公式ドキュメントで確かめ、`extraFacts` に入れてよい（ID は章ごとの範囲：ch1 F-301〜319、ch2 F-321〜339 …）。確かめられなければ書かない

## 出力

`[出力先]/work/chN.json`（N は章番号）に、次の形の JSON を UTF-8 で保存する。Python スクリプトで組み立てて `json.dump(..., ensure_ascii=False, indent=1)` で書くと、エスケープの失敗が起きにくい（スクリプトはスクラッチの場所に置く）。

```json
{
  "chapter": { "id": "ch3", "title": "…", "sections": [ … ], "exercise": [ … ] },
  "confusables": [ { "items": ["ch3-s1#i2", "ch3-s1#i3"], "note": "…" } ],
  "extraFacts": [ { "id": "F-341", "claim": "…", "url": "…", "rank": "S" } ]
}
```

- 節には `id` `title` `importance` `items` `keyPoints`（2〜6個） `sources` を入れる。ほかの章の節を指す `prerequisites` は書かない（作成担当が `work/meta.json` にまとめて書く）。同じ章の中の前提だけは書いてよい
- 書き終えたら検査する。エラーが0件、かつ警告が0件になるまで直す

```
py [SKILL_DIR]/scripts/assemble.py [出力先] --check N
```
````
