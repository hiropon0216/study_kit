# 章を書く担当（フェーズ3）

章ごとに新しいサブエージェントを立て、同時に走らせる。章どうしは別のファイル（`work/chN.json`）に書くので衝突しない。

```
Agent:
  subagent_type: general-purpose
  model: opus
  description: "第[N]章を書く"
  prompt: |
    あなたは [トピック] の教材を書く担当です。第[N]章「[章タイトル]」を書いてください。

    最初に [GEN_SPEC] を読んでください。これがあなたの要件です。章立て・固有名詞の割り当て・
    書き方・問題の作り方・出力の形は、すべてこのファイルに従います。そこに書かれた
    「必ず読むもの」を読んでから書き始めます。

    - 書くのは第[N]章だけです。ほかの章のファイルは書きません
    - 第[N]章より前の章で前提を説明済みの固有名詞：[EXPLAINED_BEFORE]
    - あなたはさらにサブエージェントを呼びません
    - 出力：[出力先]/work/ch[N].json。書き終えたら
      `py [SKILL_DIR]/scripts/assemble.py [出力先] --check [N]` でエラー0件・警告0件にする

    最後の返事は、次の表と短い報告だけにしてください。
    | 節ID | 項目数 | すぐ確認の数 | variants の数 |
    - 章末演習の数、追加した事実（extraFacts）のID、仕様の表にない固有名詞を出したならその語、
      残した警告とその理由
```

## 埋めるもの

- `[GEN_SPEC]`：`<出力先>/work/gen-spec.md`
- `[EXPLAINED_BEFORE]`：生成の共通仕様の「固有名詞の割り当て」のうち、前の章に置く語（第1章なら「なし」）

## モデル

本文と問題の質は、この担当で決まる。そのため、ほかの担当より能力の高いモデル（opus）を使う。妥当性・分かりやすさのレビューで直すより、最初によく書くほうが全体の手間が少ない。

# 総合演習を書く担当（フェーズ3）

すべての章をまとめた後に立てる。総合演習は節の数×10問以上と数が多いので、ゴールごとに分けて2〜3人で同時に書いてよい。

```
Agent:
  subagent_type: general-purpose
  model: opus
  description: "総合演習 [担当範囲] を書く"
  prompt: |
    あなたは [トピック] の教材の総合演習を書く担当です。[担当範囲（例：G1・G2 に直結する問題を40問）] を書いてください。

    ## 読むもの
    - 生成の共通仕様：[GEN_SPEC]（学習者・ゴール・問題のルール）
    - 教材の骨組み：[OUTLINE]（全章の節・項目の見出し、要点、すでにある問題の問題文と正解。
      本文は入っていない。問題を作るのに本文の細部が要るときだけ、[出力先]/content.json を
      節IDで Grep し、その節の前後だけを読む。全体を読まない）
    - 問題の作り方：[SKILL_DIR]/references/question-guide.md の「総合演習」
    - ファクトシート：[出力先]/factsheet.md

    ## 決まり
    - 複数の章の知識を組み合わせないと解けない問題にし、ゴールの「使う場面」を問う
    - すでにある問題（骨組みに載っている）と同じことを問わない
    - ID は [ID_RANGE]（例：q-final-01〜q-final-40）。`refs` には2章分以上を入れる
    - あなたはさらにサブエージェントを呼ばない
    - 出力：[出力先]/work/final_[番号].json に {"questions": [...]} の形で書く

    最後の返事は、問題数・形式ごとの数・ゴールごとの数の表だけにしてください。
```

- `[OUTLINE]`：`py <SKILL_DIR>/scripts/slice_content.py <出力先>/content.json --scope outline -o <出力先>/work/slices/outline.json` で作る
- 書き終えたら `assemble.py <出力先> --force` でまとめ直す。この時点ではまだレビュー前なので、上書きしてよい
