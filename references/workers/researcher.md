# 章ごとのリサーチ担当（フェーズ2）

章ごとに新しいサブエージェントを立て、同時に走らせる。章どうしは別のファイル（`work/facts/chN.md`）に書くので衝突しない。項目の少ない章は、2章を1人にまとめてよい（ファイルは章ごとに分ける）。

リサーチ担当が終わった章から、すぐにその章の担当（`references/workers/chapter-writer.md`）を立てる。ほかの章のリサーチが終わるのを待たない。

## 予算を決める理由

以前の運用では、リサーチ担当1人が 70〜100 回ツールを呼び、curl で取った HTML をそのまま読んで、文脈が 20 万トークン近くまで膨らんだ。ツールを1回呼ぶたびに、それまでの文脈をすべて読み直すので、回数と文脈の大きさの掛け算でトークンが増える。Web 検索もセッション全体の上限（200回）に達した。そこで、1人あたりの回数に上限を置き、ページの中身は要る事実だけを抜き出して受け取る。

```
Agent:
  subagent_type: general-purpose
  model: opus
  description: "第[N]章のリサーチ"
  prompt: |
    あなたは [トピック] の教材のための事実を集める担当です。第[N]章「[章タイトル]」の
    教科書と問題を書くのに要る事実を、信頼できる出典から集めて、ファクトシートに書いてください。

    ## 読むもの
    - 章立て（承認済み）：[CHAPTER_PLAN] の第[N]章の行と、固有名詞の一覧のうち第[N]章に置く語
    - ゴールの要約：[GOAL_BRIEF]
    - ファクトシートの書式と信頼度：[SKILL_DIR]/references/factsheet.md
    - 手元の教材の目次（あれば）：[SOURCE_TOC]

    ## 集めるもの
    - 章立ての項目（①②…）ごとに、説明と問題に使う事実。項目1つにつき3〜8行を目安にする
    - 第[N]章に置く固有名詞ごとに、前提の説明（何か／誰が作ったか／なぜ必要か／この教材との関係）に使う事実
    - 図に使う具体的な値（設定値・数値・コマンドの出力・条文の要件など）
    - 学習者が取り違えやすい点（似た用語・例外・改正前後の違い）

    ## 集め方（回数の上限を守る）
    - Web 検索は [SEARCH_BUDGET] 回まで、ページの取得は [FETCH_BUDGET] 回まで。合わせて
      [TOOL_BUDGET] 回を超えそうなら、そこで集めるのをやめて書く
    - まず、その章の範囲をまとめて説明している一次資料（公式ドキュメントの章、法令の条文、
      試験のシラバス・公式の教則、規格）を探し、1つの資料から多くの事実を取る。
      事実1行ごとに検索し直さない
    - ページは WebFetch で取り、プロンプトで「[項目] に関わる事実を、数値・条件・例外を落とさず
      箇条書きで抜き出して」のように、要る事実だけを返させる。curl などで HTML を丸ごと取って
      読まない（文脈が膨らむため）
    - 同じ事実の裏取りは1回まででよい。信頼度 S の出典が1つあれば、それで足りる
    - 集めた事実は、途中でもファイルに書き足していく（あとで書くために文脈に溜め込まない）
    - 一般に確立していて版で変わらない知識（定義・原理）も、出典の行は必要。ただし
      その章の範囲を説明した一次資料の1ページで、まとめて出典にしてよい

    ## 決まり
    - 事実の ID は F-[N]001 から連番（第3章なら F-3001、F-3002 …）。ほかの章と重ならない
    - 使用箇所の列には節番号（例：3.2）を書く
    - 信頼度 B（ブログ・Q&A）は、S で裏が取れたものだけ書き、裏付けの ID を書く
    - 見つからなかった事実は書かない。最後の報告に「見つからなかったこと」として挙げる
    - あなたはさらにサブエージェントを呼ばない
    - 出力：[出力先]/work/facts/ch[N].md（先頭に「# ファクトシート：第[N]章 [章タイトル]」と
      作成日・対象バージョン。そのあとに factsheet.md の書式の表）

    最後の返事は、次の表と短い報告だけにしてください。
    | 節 | 事実の数 | 主な出典 |
    - 見つからなかったこと、断定してはいけないと分かったこと（章の担当に伝える注意）
```

## 埋めるもの

- `[CHAPTER_PLAN]`：`<出力先>/work/chapter-plan.md`
- `[GOAL_BRIEF]`：`<出力先>/work/goal-brief.md`
- `[SOURCE_TOC]`：`<出力先>/work/source-toc.md`（なければ「なし」）
- 予算：章の項目数で決める。セッション全体の Web 検索の上限（200回）を章の数で割った値も超えないようにする

  | 章の項目数 | `[SEARCH_BUDGET]` | `[FETCH_BUDGET]` | `[TOOL_BUDGET]` |
  |---|---|---|---|
  | 〜12 | 8 | 10 | 25 |
  | 13〜24 | 12 | 15 | 35 |
  | 25〜 | 16 | 20 | 45 |

## 終わったら（作成担当）

- 報告の「見つからなかったこと」「断定してはいけないこと」を、その章の担当に渡す（`chapter-writer.md` の `[FACT_NOTES]`）
- 見つからなかった事実がゴールに欠かせないときは、その事実だけを追加で調べる担当を1人立てる（予算は検索4回・取得6回）。それでも見つからなければ、章の担当に「書かない」と伝える
